# Authentication feature

Contains the sign-in experience and API integration for Google, Facebook, and Instagram. Google and Facebook browser SDKs return access tokens that the backend verifies with their providers before creating a session; Facebook tokens are checked against the configured app ID and secret. Instagram sign-in uses a backend authorization-code exchange. Sessions use signed, user-specific bearer tokens, and `/api/auth/me` requires a valid token instead of selecting the most recently active account. For local development, open the app at `http://localhost:5173` rather than `127.0.0.1`; deployed environments must use HTTPS.

The sign-in API exposes `POST /api/auth/google`, `POST /api/auth/facebook`, `POST /api/auth/instagram`, `GET /api/auth/me`, and `POST /api/auth/logout`. Email/password registration and login, legacy channel sign-in, and generic Meta provider routes are not exposed. Google and Facebook each use one POST endpoint to verify a browser-issued access token. Instagram uses that same single POST route in two steps: send `{ "action": "start" }` to receive the provider authorization URL, then send `{ "action": "callback", "code": "...", "state": "..." }` to exchange the returned authorization code and create an ApexMind session. Instagram still requires the provider redirect internally.

Configure `GOOGLE_CLIENT_ID` on the backend to the same web OAuth client ID used by `VITE_GOOGLE_CLIENT_ID` on the frontend. For Facebook Login, configure `VITE_META_APP_ID` on the frontend and the matching `META_APP_ID` and `META_APP_SECRET` on the backend. The backend verifies the Facebook access token with Meta before creating a session. Instagram Login requires its own `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET` from **Instagram > API setup with Instagram Login > Business login settings**; do not use the Facebook App ID for Instagram. For local Instagram testing, set `META_AUTH_REDIRECT_URI` to `http://localhost:5173/login` and register that exact callback URI in the provider's login settings.

Social Accounts is available at `/social-accounts` (`/channels` remains a redirect alias). Facebook connections use `META_APP_ID` and `META_APP_SECRET` to authorize managed Pages. Instagram professional-account connections use Instagram Login with `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET` (or the Meta credentials when the same app is configured for both). For local testing, set `META_REDIRECT_URI` to `http://localhost:5173/social-accounts` and register that exact URI in the Instagram Login and Facebook Login settings. Enable `instagram_business_basic` and `instagram_business_content_publish` for Instagram Login. The connected Instagram account must be a professional account; it does not need to be linked to a Facebook Page. A personal Instagram profile or a typed handle is not a publishing destination.
