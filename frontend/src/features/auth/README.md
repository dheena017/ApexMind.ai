# Authentication feature

Contains the sign-in experience and API integration for Google, Facebook, and Instagram. Google sign-in uses an access token verified by the backend. Facebook and Instagram sign-in use authorization-code exchanges on the backend, with signed short-lived OAuth state. Sessions use signed, user-specific bearer tokens, and `/api/auth/me` requires a valid token instead of selecting the most recently active account. For local development, use `http://localhost:5173`. Add `http://localhost:5173` to the Google OAuth Web client's Authorized JavaScript origins. Deployed environments must use HTTPS and have their exact site origin registered.

The sign-in API exposes `POST /api/auth/google`, `POST /api/auth/facebook`, `POST /api/auth/instagram`, `GET /api/auth/me`, and `POST /api/auth/logout`. Email/password registration and login, legacy channel sign-in, and generic Meta provider routes are not exposed. Google uses a backend-verified browser access token. Facebook and Instagram each use a two-step POST flow: send `{ "action": "start" }` to get the provider authorization URL, then send `{ "action": "callback", "code": "...", "state": "..." }` to exchange the one-time authorization code and create an ApexMind session.

Set one `GOOGLE_CLIENT_ID` in the project environment. The backend uses it to verify Google sign-in tokens, and Vite injects that same value into the frontend's Google Identity Services client. Set the Google OAuth client secret, if required for YouTube channel authorization, as the backend-only `GOOGLE_CLIENT_SECRET`. Facebook and Instagram use separate app credentials: `FACEBOOK_APP_ID` and backend-only `FACEBOOK_APP_SECRET` for Facebook, and `INSTAGRAM_APP_ID` and backend-only `INSTAGRAM_APP_SECRET` for Instagram Login. Vite injects the Facebook app ID as `VITE_FACEBOOK_APP_ID`. Never put secrets in `VITE_` variables because frontend values are exposed in the browser. Configure `FACEBOOK_REDIRECT_URI` and `INSTAGRAM_REDIRECT_URI` for their respective Social Accounts callbacks, `FACEBOOK_AUTH_REDIRECT_URI` and `INSTAGRAM_AUTH_REDIRECT_URI` for sign-in at `/login`. Register each exact callback URL in the matching provider app's Valid OAuth Redirect URIs. For local Facebook sign-in, register `http://localhost:5173/login`; for production, set `FACEBOOK_AUTH_REDIRECT_URI` to the site's HTTPS `/login` URL. Restart both frontend and backend after changing environment values.

Social Accounts is available at `/social-accounts` (`/channels` remains a redirect alias). Facebook connections use `FACEBOOK_APP_ID` and `FACEBOOK_APP_SECRET` to authorize managed Pages. Instagram professional-account connections use `INSTAGRAM_APP_ID` and `INSTAGRAM_APP_SECRET`. For local testing, set both `FACEBOOK_REDIRECT_URI` and `INSTAGRAM_REDIRECT_URI` to `http://localhost:5173/social-accounts`, and register that callback URL in each matching provider app. Enable `instagram_business_basic` and `instagram_business_content_publish` for Instagram Login. The connected Instagram account must be a professional account; it does not need to be linked to a Facebook Page. A personal Instagram profile or a typed handle is not a publishing destination.
